# v0.1b review disposition

This note records how the independent architecture, security, specification, and maintainability findings were resolved before delivery.

## Accepted and implemented

- Natural direct-child exit now independently cleans surviving members of the original process group while preserving `exited` as the first status cause. Cancellation or child timeout during drain accelerates cleanup.
- Capture completeness is separate from model-facing truncation. Forced pipe cutoff produces a partial spool and cannot expose a complete path.
- Cancellation observed before an asynchronous spawn error remains the primary status; the spawn error is secondary metadata.
- SIGKILL metadata is set only after a successful signal request.
- Output projection and tests are invariant to UTF-8 chunk boundaries and stdout/stderr scheduling.
- Spooling is lazy, so bounded output creates no temporary filesystem state. Setup, write, assembly, and sidecar-cleanup failures are visible; permission recovery is attempted before assembly and cleanup.
- Retained output has a 64 MiB per-invocation payload cap, a 512 MiB and 256-directory aggregate quota per temporary parent, and an explicit `removeCliOutputSpool()` ownership API. Documentation records the roughly two-times assembly peak.
- Result and spool types are discriminated and readonly; duplicated complete-path state was removed and request-error codes are exported.
- Shared limits moved to `src/limits.ts`; process lifecycle, output projection, and spooling moved behind focused internal modules while `runCli()` remains the facade.
- The future adapter-wide output default is documented as tail-oriented. No registry field is added before the adapter exists.
- Runtime support is gated to Linux/macOS, fixtures use `fileURLToPath()`, and CI exercises both operating systems on supported Node versions.
- Package validation now compares an exact manifest and checks that relative README links are packaged. Repository-only documentation links are absolute.
- Tests now cover validation codes and exact boundaries, empty environment and TTY policy, first-cause races, cooperative and forced signals, escalation grace, escaped groups, confirmation/drain cutoffs, raw identity, exact and combined spool caps, permissions, quota, and explicit cleanup.

## Intentionally narrowed or rejected

### Operation-wide filesystem deadline

`timeoutMs` bounds child execution and process-group control; it does not claim to cancel every temporary-filesystem operation. Racing non-cancellable Node filesystem calls and returning early can create later, unreported files. A true storage wall-clock guarantee requires a helper process or asynchronous session-owned spool service. The contract and security documentation now state this boundary, and `durationMs` includes finalization.

### Automatic TTL or startup deletion

Automatic removal during the session was not added because the v0.1b requirement intentionally keeps returned paths available for deliberate inspection. Aggregate byte/directory quotas prevent unlimited new retention, and the consumer receives an explicit cleanup API. A future session adapter can introduce opt-in TTL policy with ownership semantics.

### Registry-to-runner mapping

No mapping helper or native tool registration was added because v0.1b is explicitly agent-independent and diagnostics-only. Introducing an unused adapter mapper would violate the project's no-speculative-abstraction rule. The future adapter's tail default and trusted mapping responsibilities are documented.

### Native Windows execution tests

Windows process execution remains unsupported rather than best-effort. Runtime validation accepts only Linux and macOS before spawn; `.cmd` and `.bat` activation therefore remains impossible. A Windows CI execution matrix is deferred until a Job Object or equivalent containment design exists.
