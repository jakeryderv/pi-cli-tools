# v0.3 review disposition

Status: **Accepted for delivery after the verification and protected-branch gates in the pull request.**

Two independent reviews blocked the initial implementation. The delivery pass reproduced the production connector defect under Node 24: a request-level `createConnection` option combined with `agent: false` was ignored, causing a second DNS resolution and an empty recorded peer. The following findings were accepted and corrected.

## Accepted findings

- **Pinned production transport:** use a one-shot `https.Agent` whose `createConnection()` dials only the prevalidated address. The callback is withheld until TLS peer verification succeeds, SNI/certificate identity remains the configured hostname, and the agent is destroyed after the request. A connector-level agent test verifies the dial policy and callback ordering; a delivery-only public-source probe exercises the production connector.
- **Authoritative aggregate snippets:** prune successful outcomes to the globally ranked eight-snippet, 24 KiB/300-line selection. Model text consumes that selection, details cannot re-expand it, and framing-aware appends keep opening and closing untrusted-data labels atomic.
- **Source reachability:** reduce the schema maximum from eight to four and process every accepted source in declaration order. No accepted source is silently sliced away.
- **Address failover and transfer accounting:** retry only pre-response connect/TLS failures. Response-policy/body failures stop the source, and failed response bytes count toward the request's aggregate transfer budget.
- **Path authorization:** use exact-or-descendant semantics rather than lexical prefix matching and reject encoded slash, backslash, dot-segment, and double-encoding markers at registry load and every hop.
- **Search/extraction bounds:** add a 10,000 normalized-line limit, retain only bounded strongest candidate windows, tokenize each line once, and check a monotonic aggregate deadline during HTML events and lexical scanning.
- **Version evidence:** apply strict SemVer 2.0 identifier validation. Replace the ambiguous `compatible` result with factual `major_match` and `major_minor_match`; prereleases and non-identical `0.x` versions remain mismatches.
- **Special-address policy:** add the IPv6 discard-only and AS112 ranges identified by review with adjacent boundary tests. Security documentation now describes a maintained deny table rather than claiming automatic completeness against future IANA assignments.
- **Lazy activation trust:** document that deferred activation scales model context and is not authorization or user approval.
- **Activation correctness:** an already-active enable is a true diagnostic no-op. Postconditions cover the complete additive union, while failures still avoid rollback to a stale snapshot.
- **HTML handling:** ignore embedded frame/object, canvas, and audio/video fallback content in addition to script/style/template/head/metadata content.
- **Middleware UX:** compact `cli_tools` rendering treats final `context.isError` as authoritative and annotates status mismatches.
- **Coverage:** add direct status, empty body, TLS classification, cache concurrency, line-bound, four-source, failed-byte-budget, framing, active-element, path, SemVer, CIDR, retry-phase, and activation-history tests.

## Intentionally bounded alternatives

- A terminable worker for at most 1 MiB of input was rejected as disproportionate v0.3 scope. Fixed body/text/line limits, bounded top candidates, and monotonic checks remove the observed allocation amplification without adding worker lifecycle and package-loader complexity.
- Generating the address table from a live IANA feed was rejected because build/runtime network authority and generated-data provenance would add a separate maintenance system. The checked-in policy is explicit, tested, and documented as maintained.
- `parse_error` remains a defensive status for unexpected parser failures. `htmlparser2` deliberately recovers malformed HTML, so tests cover reachable policy/extraction failures rather than mock parser internals solely to force that fallback.
- CI remains deterministic and network-lazy. It tests the real one-shot agent seam and packed Pi behavior without relying on public DNS or third-party uptime; the release owner separately runs one bounded production-source interoperability probe before delivery.

## Compatibility notes

- Existing definitions with zero through four official sources remain valid. Definitions with five through eight sources were accepted by the unreleased review branch only and now fail schema validation rather than containing unreachable configuration.
- The source policy name `compatible` remains accepted for registry compatibility, but returned alignment states are factual matches rather than a compatibility guarantee.
- Omitted native activation remains eager, and omitted `cli_docs.operation` remains local.
