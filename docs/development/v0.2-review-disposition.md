# v0.2 review disposition

Date: 2026-08-22

Status: **All blocking independent review findings resolved.**

Two independent reviews requested revision before delivery. This disposition reconciles each finding against the implementation. Verification evidence is recorded in the pull request and final delivery report rather than frozen here.

## Accepted and fixed

### Draining work and lifecycle

- Cancelled or invalidated loaders remain in a separate tracked-flight set until their promises settle. The concurrency limit and diagnostics count that set, while only active flights remain eligible for deduplication.
- Cache and service shutdown are asynchronous. Shutdown aborts every tracked flight, awaits bounded settlement, clears cache state, and is awaited by Pi's `session_shutdown` handler.
- Regression coverage immediately reissues work while a cancelled loader is still draining and reloads a real Pi session while a controlled introspection process is blocked.

### Outcome fidelity

- An exited introspection process is successful only when capture is complete, its exit is explicitly accepted, and natural process-group cleanup is confirmed without error.
- Capture, exit, signal, timing, termination/cleanup, and bounded error-code metadata flow through core outcomes into Pi details. Collapsed rendering flags capture or cleanup uncertainty.
- Unaccepted man exits remain `unaccepted_exit` failures. v0.2 does not infer a portable missing-page exit code. If a fallback helper is missing, an earlier operational help failure remains the primary result.

### Identity coherence and deadlines

- One target identity is established for an aggregate request and supplied to every source. It is verified before cache lookup, around each execution, and before aggregate return.
- Fingerprinting resolves first and then stats/accesses the resolved path rather than combining concurrent observations of the lexical and resolved paths.
- Filesystem discovery, helper resolution, and fingerprint phases check or race aggregate cancellation. Underlying Node filesystem calls may continue because they are not reliably cancellable in-process; this limitation is documented.

### Subcommand safety and executable templates

- Subcommand help requires exact registry `allowed_paths` in addition to lexical validation. The bundled GitHub definition disables subcommand help because arbitrary GitHub aliases and extensions can execute behavior.
- Registry validation reserves the full eight-segment/512-byte selector budget: append suffixes allow at most 120 arguments and 32 KiB minus 512 bytes. Every valid allowed selector and suffix therefore fit the runner's final limits.

### Cache integrity and privacy

- Keys and success values are cloned at cache boundaries and each waiter receives an independent clone, preventing returned-object mutation from poisoning entries or byte accounting.
- Diagnostics report only that a version is cached and never render executed version output.
- Structured details have an explicit 192 KiB ceiling, omit commands if the ceiling would otherwise be exceeded, strictly validate nested persisted shapes before rendering, and bound call previews and unknown-selector errors.

### Pi contract and smoke evidence

- The tool description now says it does not fetch remote documentation rather than claiming executed CLIs cannot use the network, and asks callers to prefer an allowed subcommand when known.
- Packed smoke parses actual JSONL newlines, counts every invocation after cache calls, exercises both bundled selectors, verifies cache isolation, and uses a controlled man helper to prove startup laziness and one successful fallback execution. Failed help is intentionally retried because v0.2 has no negative cache.
- Tests now cover draining concurrency, aggregate cancellation, explicit nonzero documentation exits, cleanup uncertainty, mutable return handles, allowlists, reserved selector budgets, malformed details, details/call bounds, actual truncation rendering, real Pi documentation failure middleware, and blocked-flight reload cleanup.

### Documentation corrections

- ADR-0003 is accepted, dated 2026-08-22, and renamed `0003-session-local-introspection.md`.
- README, security boundaries, lifecycle handoff, and the canonical roadmap describe allowlists, coherent identity, asynchronous draining, cleanup-success requirements, filesystem limits, details disclosure, and smoke behavior accurately.

## Intentionally retained or rejected concerns

### Exact executable path, argv, cwd, and identity digests

The recommendation to remove exact paths/cwd and the definition/executable digests from serialized provenance was rejected because the v0.2 acceptance contract explicitly requires exact executable path, final argv, cwd, and definition/executable digests for auditability and cache provenance. The privacy concern is valid and is mitigated by:

- Removing version text from human diagnostics
- Explicit details and model-output bounds
- Omitting command provenance only if the details ceiling would otherwise be exceeded
- Documenting that Pi session history and exports can reveal usernames and installation layouts

Environment values and their digest remain unexposed.

### A dedicated “page unavailable” exit policy

The reviews suggested an optional explicit missing-page exit list. That additional policy was not added because no bundled definition requires it and it would be speculative API surface. Missing helpers remain unavailable; all executed helper exits use the ordinary explicit accepted-exit policy and preserve failure metadata.

### True filesystem wall-clock cancellation

In-process Node filesystem promises cannot be reliably cancelled. The service stops awaiting them at the aggregate deadline and does not launch later phases, but an external supervisor would be required to guarantee that kernel/filesystem work itself has ended. This remains a documented residual risk rather than an in-process claim.

## Scope confirmation

The disposition adds no remote fetching, semantic query, persistent or negative cache, lazy activation system, rich per-CLI execution schema, project registry layer, or Windows execution support.
