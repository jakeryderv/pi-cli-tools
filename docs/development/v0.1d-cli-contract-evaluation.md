# v0.1d CLI contract evaluation

## Purpose

v0.1d evaluates the generic native-CLI contract with two contrasting bundled definitions: authenticated, environment-inheriting GitHub CLI and local, empty-environment ripgrep. It is a hermetic adapter evaluation, not a compatibility or conformance suite for either third-party CLI.

After npm dependencies are installed, the deterministic contract tests use temporary controlled executables named `gh` and `rg`. They do not depend on globally installed CLIs and make no GitHub, authentication, or third-party CLI network requests. The fixture protocol supplies deterministic process outcomes; it does not emulate either CLI's complete syntax or behavior. CI dependency installation, `npm audit`, and the packed smoke test's fresh production install may contact the npm registry.

## Automated evidence

| Contract concern            | Deterministic evidence                                                                                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Production registry         | Loads `github` and `ripgrep` in stable ID order; verifies default `[0]` and ripgrep `[0, 1]`.                                                                                         |
| Strict policy validation    | Covers omitted, explicit, boundary, empty, duplicate, fractional, non-finite, string, out-of-range, oversized, unknown-field, complete-replacement, provenance, and quarantine cases. |
| Multiple registration       | A real `DefaultResourceLoader` and Pi session register both production definitions with the same strict `{ args: string[] }` schema.                                                  |
| Availability and reload     | Starts with one fixture missing, creates it and reloads, then removes the other and reloads through public session lifecycle.                                                         |
| Startup behavior            | Verifies discovery and reload do not invoke either executable or execute declared version/help commands.                                                                              |
| Argument and cwd boundaries | Passes spaces, an empty argument, glob and shell metacharacters, quotes, backticks, and command-substitution text literally; verifies exact session cwd and no shell marker.          |
| Environment policy          | Verifies `cli_gh` sees a controlled inherited sentinel and `cli_rg` receives no sentinel.                                                                                             |
| Ripgrep domain outcome      | Preserves exit 1 as `status: exited`, `exitCode: 1`, and classifies it as accepted only for ripgrep.                                                                                  |
| Error outcomes              | Verifies exit 2 is an error and that signals, timeout, cancellation, spawn errors, and request errors remain errors under accepted-exit configuration.                                |
| Pi middleware               | Exercises accepted exit 1 and unaccepted exit 2 through the real provider/tool-result pipeline and preserves an earlier middleware error decision.                                    |
| Output bounds               | Exercises output above 48 KiB, deterministic tail projection, final Pi limits, complete raw spool retention, and explicit cleanup.                                                    |
| Human diagnostics           | Shows bounded timeout, session cwd, environment mode, and non-default accepted exits for available and missing definitions.                                                           |
| Packaged production loading | Packs and production-installs the tarball, loads both bundled definitions from the installed package, and executes controlled `gh` and `rg` without user overrides.                   |

Primary automation lives in `tests/cli-contract-evaluation.test.ts`, with focused registry, adapter, extension, lifecycle, runner, and package-smoke coverage in the existing suites. The standard evidence commands are:

```bash
npm run check
npm run security:audit
npm run smoke:pi
```

## Supplementary local observation

On 2026-08-22, a non-gating probe used `/usr/bin/rg` (`ripgrep 14.1.0`) with an empty environment and `--no-config` on Linux x86-64, Node.js 24.14.0, and Pi 0.84.2. A fixed-string match exited 0, no match exited 1, and an invalid regular expression exited 2. This one-machine observation supports the bundled policy but is not CI evidence or an exhaustive conformance claim. GitHub CLI was not probed.

## Not measured

- Model tool-selection quality or superiority over a shell-only baseline
- Real GitHub API behavior, authentication, aliases, extensions, editors, browsers, or remote mutation
- Exhaustive ripgrep syntax or platform conformance
- Broad host-installed CLI compatibility or performance
- Network or authenticated workflows
- Native Windows execution

No claim about model-selection improvement or third-party CLI conformance follows from this milestone.

## Residual risks and limitations

- Both tools execute with the Pi process's filesystem and operating-system permissions; accepted exit codes are classification policy, not a safety guarantee.
- GitHub CLI inherits credentials and configuration. Ripgrep receives an empty environment but can still expose local secrets or broaden access through CLI flags.
- CLI and repository output is untrusted, can contain prompt injection, persists in Pi history, and may remain in sensitive temporary spools until explicit cleanup.
- The generic adapter uses tail selection for all output. Search-oriented ripgrep results may be less useful when truncated because early matches can be omitted.
- Version/help and official documentation declarations are validated metadata only. v0.1d does not execute introspection, add `cli_docs`, or retrieve remote documentation.
