# v0.2 independent review handoff

Status: **Independent review completed; findings reconciled for delivery.**

This note preserves the original review surface. Accepted fixes and intentionally rejected concerns are recorded in the separate [v0.2 review disposition](./v0.2-review-disposition.md).

## Implemented scope

- Strict explicit registry commands for installed version, top-level help, subcommand help, and optional configured man retrieval
- Bounded startup with no introspection command execution
- Agent-independent local introspection service and bounded success-only memory cache
- Non-retaining runner capture through the existing shell-free process and POSIX cleanup boundary
- One shared lifecycle-registered `cli_docs` Pi tool with strict dynamic selection, post-middleware validation, ownership checks, bounded model content and serializable details, error middleware, and TUI rendering
- Executable/definition/environment/cwd/source/subcommand-aware cache keys, coherent identity rechecks, clone boundaries, LRU bounds, concurrent-flight deduplication, waiter-aware cancellation, draining-flight accounting, and awaited shutdown clearing
- Controlled local fixtures, real Pi lifecycle/reload coverage, and packed production smoke coverage
- README, security, canonical design/roadmap, ADR, package manifest checks, and lifecycle updates

## Explicitly out of scope

- Remote or official-documentation fetching
- Version-alignment claims for official URLs
- Focused semantic or natural-language documentation search
- Persistent or negative caches
- Lazy native-tool activation or registry search/enable tools
- Rich per-CLI execution schemas
- Windows execution support

## Independent review checklist

Reviewers should verify:

1. Factory loading, `session_start`, repeated startup, `/cli-tools`, and reload do not run version/help/man commands.
2. Registry unknown-field rejection, provenance, complete replacement, tombstones, override quarantine, duplicate handling, and `cli_docs` reservation remain fail closed.
3. `cli_docs` cannot select a registry ID, candidate, executable, cwd, environment, stdin, page, URL, raw command, option-like subcommand, or arbitrary argument.
4. Final argv construction preserves element boundaries and uses only exact discovered/helper paths plus registry templates and validated subcommand segments.
5. Local execution retains runner validation, timeout, cancellation, signal metadata, process-group cleanup, deterministic stream order, and no-spool overflow behavior.
6. Generic native accepted exits never implicitly authorize documentation-command success.
7. Cache keys cannot collide across registry IDs, definitions, target/helper identities, sources, argv/subcommands, cwd, or environment snapshots.
8. Only complete successful sanitized results with confirmed cleanup enter cache; failed, unavailable, cancelled, timed-out, signalled, incomplete, cleanup-uncertain, and unstable results remain uncached.
9. Identical concurrent calls share work, one waiter can cancel independently, all-waiter cancellation stops the child, and shutdown/reload prevents old flights from populating new state.
10. Model text and TUI output remain bounded, attributed, sanitized, and consistent with final Pi `isError`; details do not duplicate manual text.
11. Missing, disabled, quarantined, colliding, unsupported, registration-failed, and ownership-changed states remain clear without duplicate shared registration.
12. The packed smoke uses only controlled binaries and proves `cli_docs` registration, startup laziness, exact version/help/man argv, two-CLI schema use, success-only cache behavior, and cache isolation.
