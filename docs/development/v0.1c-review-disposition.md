# v0.1c review disposition

This note records how the independent native-tool security and specification reviews were resolved before delivery.

## Accepted findings

- **Malformed attributable tombstones:** registry parsing now recovers one unambiguous schema-valid top-level ID directly from the YAML document AST when unrelated parse, warning, or conversion errors occur. Ambiguous duplicate `id` keys remain unattributed. Recovered IDs quarantine matching lower definitions from execution.
- **Quarantine conflict ordering:** quarantined IDs are excluded before final executable tool-name conflict calculation, so a withheld definition cannot suppress an otherwise eligible definition.
- **Tool-result middleware:** successful results now omit an `isError` patch, preserving decisions from earlier middleware. Error patches require both a registered tool name and its matching registry ID.
- **Dynamic ownership:** activation records the adapter tool's Pi `sourceInfo`. `/cli-tools` compares current provenance and reports `[ownership_changed]` when a later dynamic registration changes the effective owner.
- **Diagnostics:** bounded source, nested candidate/path, ownership, registration, and registry sections are restored under one final 50 KiB/2,000-line notification limit.
- **Partial rendering:** incomplete tool arguments render as `(arguments pending)` instead of throwing.
- **Lifecycle documentation:** factory-time `registerTool()` is documented as legal but intentionally deferred because discovery needs session cwd and collision preflight needs post-bind action methods.
- **Cleanup metadata:** no-spool results mark cleanup as not applicable. Retained artifacts identify `pi-cli-tools` as owner, and failed spools warn when sidecars remain.
- **Test realism:** coverage now includes two eligible registrations, a faux-provider Pi tool-call pipeline, public `AgentSession.reload()`, real late ownership replacement, actual partial/failed spool outcomes, malformed-tombstone activation, worst-case diagnostics, and loading a production-only install of the packed tarball.
- **Current feature description:** README text no longer claims that version-aware introspection or on-demand documentation is implemented.

## Intentionally retained behavior

- **Per-tool registration failure handling:** current Pi's `registerTool()` stores definitions synchronously and normally does not throw. The adapter still records thrown registration failures because the v0.1c status contract requires registration errors to remain diagnostic-visible and future/runtime implementations may reject registration. The mock test is a defensive error-path test, not evidence that current Pi reports collisions by throwing.
- **Reload-based refresh:** no in-place watcher or unregister emulation was added. Pi's public `session.reload()` is now tested for missing-to-present and present-to-missing transitions.
- **Explicit spool retention:** v0.1c does not delete retained output at session shutdown or reconstruct paths from imported history. This preserves the reviewed runner retention policy; ownership and operator/host cleanup responsibilities are now explicit.
- **Collision guarantee:** the adapter never overrides a tool visible during registration preflight. Pi still has no atomic conflict result or unregister API, so later dynamic ownership changes are detected and reported rather than prevented.

## Scope decision

Quarantine changes remain in v0.1c rather than being split into a separate registry release. Fail-closed behavior for invalid and duplicate higher-precedence entries is an explicit native-execution acceptance criterion and becomes security-significant only when registry definitions become callable.
