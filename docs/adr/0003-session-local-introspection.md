# ADR-0003: Use explicit session-local introspection with success-only memory caching

- Status: Accepted
- Date: 2026-08-22
- Deciders: Project maintainers

## Context

v0.2 adds installed-version, help, subcommand-help, and optional man-page retrieval. These commands must remain absent from startup, use the same shell-free process boundary as native execution, avoid placing manuals in the permanent prompt, and prevent stale or cross-CLI cache reuse.

Pi can register tools after binding during `session_start`, but it has no tool-unregistration API. Reload and session replacement create a new extension runtime and emit `session_shutdown`. Pi middleware can also mutate validated tool inputs without another schema-validation pass.

Local help and man text is untrusted and can be large, terminal-formatted, version-dependent, environment-dependent, or generated by replaced executables. Generic native accepted-exit policy is not documentation-command policy: for example, a search command's accepted no-match exit does not imply that help succeeded.

Concurrent model tool calls can request the same documentation. Independent duplicate children waste resources, but cancellation of one caller must not terminate work still needed by another caller.

## Decision

v0.2 will:

- Keep registry loading and executable discovery at startup but execute no version, help, man, or network command until an explicit `cli_docs` call.
- Extend strict registry introspection declarations with optional command-specific accepted exits/timeouts and an explicit man-helper candidate plus fixed argv object. `man: false` remains valid; guessed `man: true` is rejected.
- Reserve the Pi name `cli_docs` and register one shared tool after eligible native CLI registration during `session_start`.
- Expose only an exact registered native-tool selector and an optional bounded ASCII subcommand path that must exactly match a registry-declared allowlist. The adapter revalidates input after middleware and verifies current native-tool ownership. The bundled GitHub definition leaves subcommand help disabled because aliases and extensions can execute behavior.
- Keep the introspection service and cache agent-independent. Pi lifecycle, TypeBox schemas, middleware classification, model formatting, and TUI rendering remain in the adapter.
- Reuse the runner's request validation, direct `spawn(..., { shell: false })`, environment snapshotting, ignored stdin, no-TTY policy, POSIX process-group supervision, cancellation, and timeout behavior.
- Add a non-retaining runner capture path with configurable smaller head limits. Introspection overflow is discarded and never written to raw-output spools.
- Limit each command to the tighter of its configured timeout, native execution timeout, and ten seconds; trigger aggregate request cancellation after fifteen seconds while retaining the runner's bounded cleanup settlement semantics. Race that cancellation around filesystem phases while acknowledging that in-process Node filesystem work itself cannot be cancelled reliably.
- Retrieve version alongside requested local documentation. Top-level help may fall back to explicitly configured man; subcommand help never falls back to top-level or man material.
- Give man a controlled locale/pager environment and resolve its configured helper lazily to an exact real path. Man implementations and formatter helpers are not treated as sandboxed.
- Sanitize terminal sequences, carriage rewriting, overstrikes, control characters, and Unicode format characters before cache and model exposure, while framing all local text as untrusted reference data.
- Use a bounded extension-instance memory cache keyed by complete definition digest, registry ID, exact target/helper file identities, source, argv/subcommand, cwd, and environment-snapshot digest. Clone values across the cache boundary so callers cannot mutate stored entries or accounting.
- Establish one coherent target identity for the aggregate request and verify it before lookup, around each execution, and before return. Cache only complete successful sanitized outcomes with confirmed process cleanup; never cache missing sources, rejected exits, signals, spawn failures, timeouts, cancellations, capture cutoffs, cleanup uncertainty, or identity changes.
- Deduplicate concurrent identical misses. One cancelled waiter detaches; the shared child is aborted only when every waiter cancels. Count aborted/draining loaders against the distinct-flight bound until settlement.
- Abort and await bounded flight settlement before completing `session_shutdown`; reload starts with a new cache.
- Keep documentation accepted exits separate from generic native execution accepted exits.
- Keep remote fetching, official-documentation alignment, semantic search, persistent caching, lazy activation, rich per-CLI schemas, and Windows support outside v0.2.

## Consequences

### Positive

- Startup remains bounded and deterministic.
- The model cannot reinterpret templates as shell text or select another executable, cwd, environment, page, URL, or raw command.
- Local syntax corresponds to the selected executable identity and relevant execution context, subject to documented TOCTOU and interpreter limitations.
- Repeated and concurrent requests avoid duplicate complete work without turning one caller's cancellation into another caller's cancellation.
- Cache contents, structured details, and model output have explicit memory, byte, line, lifecycle, and provenance boundaries.
- Documentation failures cannot inherit permissive native exit policy or poison successful cache entries.
- Reload naturally handles changed definitions, availability, registrations, and cache state without emulating tool unregistration.

### Negative

- Every uncached request performs filesystem identity checks and may launch both version and help processes.
- A complete target fingerprint based on file metadata is not a content hash and cannot eliminate every adversarial replacement race.
- Inherited-environment cache identities may reduce hit rates when unrelated variables change.
- A man helper can invoke formatter processes through `PATH`; pager neutralization is defense in depth, not containment. Unaccepted man exits remain operational failures because no portable missing-page exit policy is inferred.
- Failed results are retried because v0.2 intentionally has no negative cache.
- The shared tool is unavailable when another owner already has `cli_docs`, and later ownership replacement can only be detected, not prevented atomically.

## Alternatives considered

### Run version/help during startup

This would make metadata immediately available but violates the bounded-startup contract, can hang or trigger plugin/config/network behavior, and destabilizes prompt metadata.

### Expose raw command, executable, page, cwd, or environment inputs

This would be more flexible but turns documentation lookup into a second generic process runner and weakens registry authority and cache isolation.

### Use generic native accepted exits

This conflates domain command semantics with documentation retrieval and could cache plausible text from a failed help operation.

### Use `pi.exec` or a separate spawn implementation

`pi.exec` is not the reviewed execution boundary for this project, and a second process implementation would duplicate cancellation, timeout, cleanup, validation, and output risks.

### Persist cache entries to disk

Disk persistence adds untrusted parsing, permissions, eviction, stale identity, cleanup, and cross-session poisoning concerns before operational evidence justifies it.

### Give every CLI its own documentation tool

Per-CLI tools enlarge the permanent tool surface and duplicate schemas/rendering. One strict shared selector is sufficient for the current registry.

### Let each concurrent caller own a child

This preserves simple cancellation semantics but causes avoidable process amplification. Waiter-aware shared flights retain independent caller cancellation while bounding duplicate work.

## Review triggers

Revisit this decision when:

- Remote official documentation or persistent caches enter scope.
- Pi provides atomic tool registration conflicts or tool unregistration.
- Content hashing or an external supervisor is required to strengthen executable identity.
- Operational evidence shows inherited-environment identity causes unacceptable cache churn.
- Man retrieval requires a portable helper profile beyond Linux/macOS.
- Native Windows process supervision is designed.
